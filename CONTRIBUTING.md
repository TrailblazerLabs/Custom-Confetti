# Contributing to Trailblazer Labs

Thank you for helping us build the future of the Salesforce ecosystem! All community assets in this program are open-source and governed by the **Apache 2.0 License**.

## How You Can Contribute

### 1. Report a Bug
If you find a issue, search our **Issues** tab first to see if it has already been reported. If not:
* Open a new issue using the **Bug Report** template.
* Include reproduction steps, environment details (e.g., Scratch Org, Developer Edition), and screenshots.

### 2. Suggest Improvements
Have an idea to extend this solution?
* Open an issue using the **Feature Request** template.
* Detail the business case, target user persona, and proposed solution.

### 3. Submit Code or Declarative Changes
We welcome Pull Requests (PRs) from all tracks (No-Code, Low-Code, and Pro-Code)!
1. **Fork** this repository and create a feature branch (`git checkout -b feature/my-enhancement`).
2. **Build & Test:** Ensure all Apex unit tests pass (minimum 85% coverage) and Flows/LWCs follow standard Salesforce security guidelines.
3. **Document:** Update `/docs/USER-GUIDE.md` or `/docs/ARCHITECTURE.md` if your changes alter setup steps or platform design.
4. **Submit PR:** Open a Pull Request against the `main` branch with a clear summary of your changes.

---

## Maintenance Model & Community Handoff

This project operates under the **Builder in Residence 180-Day Commitment**:
* **Days 1–180:** The primary author serves as Lead Maintainer (triaging issues, reviewing PRs, and releasing patches).
* **Day 181+:** The project transitions to Community Governance, where co-maintainers from the Trailblazer Labs community take over repository maintenance.

All contributors are expected to adhere to our inclusive Code of Conduct. Respectful, constructive feedback is required at all times.
